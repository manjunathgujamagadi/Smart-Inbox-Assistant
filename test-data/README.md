# Synthetic test data

Everything here is fabricated for testing (fictional patients, fictional products: Neptazol,
Ferbolex, Cortivex Cream, Sedaprin, Glucoreg). No real patient or client data was used anywhere,
per the assignment's ground rules.

Generated by [`generate_test_data.py`](generate_test_data.py) (reportlab + Pillow), using the
[Caveat](https://fonts.google.com/specimen/Caveat) handwriting font (`fonts/Caveat.ttf`, SIL Open
Font License) to simulate the hand-completed forms. Re-run it to regenerate everything from
scratch:

```bash
cd test-data
python3 -m venv .venv && . .venv/bin/activate
pip install reportlab pillow
python3 generate_test_data.py
```

`emails/*.json` fixtures are what `POST /api/batch/run` ingests (see
`LocalBatchIngestionService`); each `attachments` entry is a path to a PDF under `pdfs/`.

## Coverage of Section 6 requirements

| # | Requirement | Where |
|---|---|---|
| 1 | ≥10 emails, varying detail about a reaction | `icsr-01`..`icsr-06`, `icsr-07-es`, `icsr-08-fr`, `article-email-01`..`05` (13 total) |
| 2 | ≥5 normal digital PDF attachments | `icsr-01-form`, `icsr-02-labs`, `icsr-04-form`, `pqc-01-complaint`, `pqc-02-complaint` |
| 3 | ≥2 scanned/handwritten-style PDFs | `icsr-05-handwritten`, `icsr-06-handwritten` (rendered with a handwriting font onto a page image, no text layer — see write-up) |
| 4 | ≥5 fictional "article" PDFs | `article-01`..`article-05` (each attached to its own `article-email-*`) |
| 5 | ≥2 non-English PDFs, case-relevant | `icsr-07-es-form` (Spanish), `icsr-08-fr-form` (French) |
| 6 | ≥2 quality-complaint-only, ≥2 info-request-only | `pqc-01`, `pqc-02`; `mi-01`, `mi-02` |
| 7 | ≥1 clearly irrelevant example | `irrelevant-01` (marketing email) |

18 emails / 14 PDFs total — comfortably over the "10-15 documents" batch-run minimum regardless of
whether "document" is counted per email or per PDF.

## Bonus: literature-screening samples

[`literature-samples/`](literature-samples/) holds two article PDFs for the Section 4 bonus (upload
via `POST /api/literature/upload`, not part of the Section 6 count above): `lit-multi-case.pdf`
describes two distinct real patient cases (tests case-splitting), `lit-no-case.pdf` describes none
(tests the zero-case path). See the write-up (§10) for what this uncovered.

## Notable extraction-testing details

- `icsr-01-form.pdf` and `icsr-02-labs.pdf` each include a real vector-drawn table (vitals / lab
  values) to exercise structured table extraction.
- `pqc-01-complaint.pdf` embeds a synthetic "damaged bottle" illustration (drawn, not a real photo)
  to exercise the meaningful-image description pipeline.
- `icsr-04` is deliberately both an ICSR and a PQC (a contaminated product caused the reaction) to
  exercise multi-label classification.
- `icsr-03` is deliberately vague (no attachment, unclear dates/roles) to exercise "Not stated"
  field handling rather than guessing.
